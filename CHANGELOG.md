Each release also gets autogenerated notes from goreleaser on the GitHub
Releases page; this file is the curated companion.

## v0.4.6 (2026-05-08)

**Bug fixes**

- **Claude plugins now load correctly inside the box.** `~/.claude/plugins/installed_plugins.json` and `known_marketplaces.json` embed absolute host paths in `installPath` / `installLocation` fields (e.g. `/home/<user>/.claude/plugins/cache/<marketplace>/<plugin>/<ver>`). Claude opens those paths verbatim, so they must resolve inside the container. Previously `~/.claude` was bind-mounted at `/root/.claude` (HOME=/root), making those host-absolute paths point at nothing — all installed plugins, skills, and slash commands silently disappeared. Fix: apply agentbox's existing same-path principle to all home-directory mounts. `~/.claude`, `~/.claude.json`, `~/.gitconfig`, `~/.ssh`, shell history, and saved/ are now mounted at the host's HOME path inside the box, and `HOME` is set to mirror the host. Container still runs as uid 0 (HOME is just an env var). The host path is derived from `os.UserHomeDir()` so it works on any machine.
- **IPv6 disabled inside the box.** agentbox-managed Podman networks are v4-only and the `safe`/`allowlist` iptables+ipset plumbing has no IPv6 equivalent. Without this, AAAA queries resolve via CoreDNS but TCP connects to the returned v6 address hang indefinitely (no v6 route from the box), causing mysterious plugin and MCP failures in dual-stack-aware tooling. Fix: `--sysctl net.ipv6.conf.all.disable_ipv6=1` (and `default`) at container create time.

**Improvements**

- **Default `network.allowlist` expanded** to cover all three default agents when `network.mode = "allowlist"`: adds `mcp-proxy.anthropic.com`, `api.openai.com`, `files.pythonhosted.org`, `proxy.golang.org`, `sum.golang.org`, `api.github.com`, `raw.githubusercontent.com`, `objects.githubusercontent.com`, and `codeload.github.com`.
- **`scripts/net-diag.sh`** — companion diagnostic with `probe`/`tail`/`drops`/`watch` subcommands for diagnosing in-box connectivity (v4+v6 reachability of common agent endpoints, CoreDNS query log tail, iptables DROP counters and ipset size).

## v0.4.5 (2026-05-07)

**Bug fixes**

- **`claude` kit:** `claude-mode` post-install check (`command -v claude-mode`) failed in v0.4.4, taking down every published kit-image leg that includes the claude kit (`polyglot-containers-claude`, `polyglot-claude`, `node-claude`) on the v0.4.4 `kit-images` run. Root cause: `CLAUDE_MODE_INSTALL=/usr/local/bin curl … | sh` placed the env assignment on the **left** side of the pipe, where POSIX shells scope it to `curl` only — `sh` (the consumer that actually runs the upstream installer) never saw it, so the installer fell back to `$HOME/.local/bin` (= `/root/.local/bin` in the build container), which isn't on `PATH`. Move the assignment onto `sh` so it's part of the consumer's environment. v0.4.4 users hit the same failure on the local-build fallback path too — the broken `install.sh` is embedded into the v0.4.4 binary via `//go:embed` — so this fix requires a release, not just a CI rerun.



**Features**

- **`agentbox run --mode <preset>` integrates [claude-mode](https://github.com/nklisch/claude-code-modes).** When set, the agent pane runs `claude-mode <preset> --dangerously-skip-permissions` instead of bare `claude`, launching Claude Code under a behaviorally-tuned system prompt. Built-in presets: `create`, `extend`, `safe`, `refactor`, `explore`, `debug`, `methodical`, `director`, `partner`, `none`. User-defined presets in `.claude-mode.json` are also accepted. Empty `--mode` is a byte-identical no-op; pairing `--mode` with a non-claude agent (codex, opencode) exits 2 with a clear error. Dry-run shows `# mode = <preset>` between `# network` and `# layout` when the flag is set. See [docs/features/claude-mode.md](docs/features/claude-mode.md).
- **`claude-mode` binary preinstalled in the `claude` kit.** `install.sh` now runs the upstream `curl | sh` installer with `CLAUDE_MODE_INSTALL=/usr/local/bin` after `@anthropic-ai/claude-code`, so `which claude-mode` resolves inside any box built with the claude kit. `CLAUDE_MODE_VERSION` is read for forward-compat (upstream doesn't yet pin versions).

**Internal**

- New pure helper `lifecycle.BuildAgentCmd(base []string, mode string) ([]string, error)` — defensive-copy semantics, claude-only validation, no preset-name validation (claude-mode owns that). Six unit tests, three lifecycle KDL-inspection tests, and three CLI dry-run tests.

## v0.4.3 (2026-05-07)

**Features**

- **Global Claude skills and plugins now work inside the box.** `~/.claude/skills/` and `~/.claude/plugins/` often contain symlinks that target paths outside `~/.claude` (e.g. `~/.claude/skills/foo → ~/.agents/skills/foo`). A raw bind-mount preserved those symlinks but left their targets unreachable inside the container, so global skills silently dangled. Fix: at box-create time agentbox walks `~/.claude` for external symlink targets, then bind-mounts each at its same host path. Preserved symlinks resolve correctly and host↔box sync stays live — everything is still a bind-mount, not a copy.

**Improvements**

- **`--quiet` (`-q`) now actually suppresses non-error output.** Status confirmations ("removed abc123", build result lines, "no boxes"), informational lifecycle prints, and doctor OK/WARN lines are all gated on `--quiet`. Errors and primary output (table rows, JSON, dry-run shell) are never suppressed.
- **`agentbox rm --all` prompts for confirmation** (`Remove N box(es)? [y/N]`) when stdin is a TTY. `--force` skips the prompt; non-TTY input (scripts, CI) still requires `--force`.
- **`agentbox rm <id>` prints "removed <id>"** on success; `rm --all` prints a "removed N box(es)" summary.
- **`agentbox ls` prints "no boxes"** (to stderr) when the list is empty.
- **`--dry-run` on `agentbox rm`** prints the exact `podman stop / podman rm / podman network rm / rm -rf` sequence without executing it. Skips the confirmation prompt. Reflects `--keep-state`.
- **`--dry-run` on `agentbox build`** prints the equivalent `podman pull` + `podman tag` (when pull-eligible) or `podman build` command without building. Mutually exclusive with `--print`, `--print-tag`, `--list`, `--prune`, `--emit-context`.
- **`--detach-on-exit` on `agentbox run` is implemented.** When the user's zellij session ends, agentbox stops the container. Stop failures print a warning to stderr without affecting the session exit code. `--no-attach + --detach-on-exit` is rejected at parse time (exit 2).
- **`agentbox config show --effective` flag removed.** The flag was silently ignored; cobra now rejects it with "unknown flag: --effective" (exit 2). The underlying `--config`/`--runtime`/`--no-project-config` overrides from `loadConfig` were always reflected in `config show`.
- **`agentbox shell` gains `--fresh`** (documented; was already functional).

**Internal**

- ~100 LOC consolidated across 8 refactor steps: `ContainerName`/`NetworkName` canonicalized in `internal/container`; `state.EnsureFile` helper (fixes a silent-error path in `.claude.json` self-heal); `internal/paths` package with shared `ExpandHome`; `Lifecycle.info`/`warn` quiet-aware methods; `network.Manager.Stderr` field for capturable warnings; per-session path helpers in `state`; `resolveConfigTarget` in config commands; `initLifecycleCmd` de-duplicates CLI command prelude across 6 commands.
- Nine code patterns documented under `.claude/skills/patterns/` for agent consistency.

## v0.4.2 (2026-05-07)

**Bug fixes**

- **`agentbox run` / `agentbox shell`:** layout KDL write-after-mount race on macOS Podman. `state.EnsureSession` touches `<state>/layout.kdl` as a 0-byte file so the bind mount has a target; previously `writeLayoutFor` populated the real KDL only **after** `EnsureBox` had already triggered `podman create`. On Linux this works because host writes to a bind-mounted file propagate to the guest. On macOS the bind mount goes through the podman-machine VM's virtiofs, which caches the file's empty inode at mount time — the guest can keep serving 0 bytes (or torn content during the host write), so zellij sees an empty/broken layout file and aborts with a parse error on first run. Most visible on a fresh-install Mac with a cold virtiofs cache. Fix: hoist `writeLayoutFor` to before `EnsureBox` in both `Run` and `Shell` so the bind-mount source has its final content at create time. Linux behavior is unchanged; the post-`EnsureBox` call is retained as a defensive refresh for the reattach path.
- **No race on `effective-config.toml` or `claude-settings.json`.** Both were already written before `Runtime.Create` (`writeEffectiveConfig` at lifecycle.go:147; `WriteShadowSettings` for auditor+claude at lifecycle.go:183-188). Only `layout.kdl` was post-mount.

**Tests**

- **Isolation test for the race** (`internal/lifecycle/layout_at_create_test.go`): a `snapshotRuntime` reads the host bytes of every `/etc/agentbox/*` bind-mount source at the precise moment `Runtime.Create()` is invoked. Asserts `layout.kdl` is non-empty and contains the expected layout block. Catches the race on Linux CI without needing podman, virtiofs, or a Mac. Reverting the fix in-place fails all four production tests with a diagnostic naming the race; the counter-test (bare `EnsureSession` leaves file empty) and a snapshot-mechanism check stay green.
- **End-to-end artifact validation** against real consumers — closes a long-standing gap where the existing fragment tests validated artifacts with the same Go libraries that produced them and could not detect malformations zellij or Claude Code would reject:
  - `internal/zellij/parse_realzellij_test.go` pipes generated KDL through real `zellij --layout <path> setup --check` (exit 1 + "Failed to parse" → fail). Skips when `zellij` isn't on PATH so `go test ./...` stays green on machines without it.
  - `internal/lifecycle/settings_realparser_test.go` decodes the shadow `claude-settings.json` into a typed struct that mirrors Claude Code's hooks schema and, when `jq` is on PATH, runs filters that mirror what Claude Code's hook loader queries.
- **`make test-e2e`** runs both with `-count=1` and a clear PASS/SKIP signal.

## v0.4.1 (2026-05-06)

**Bug fixes**

- **`containers` kit:** `docker-compose` install URL was using the Go-style arch (`amd64`/`arm64`) but docker/compose ships binaries with the raw `uname -m` suffix (`x86_64`/`aarch64`). Both arches 404'd in CI on the kit-images workflow's first run for v0.4.0; pulled-image consumers wouldn't have hit it (since the publish step itself failed) but anyone building locally with the `containers` kit on a fresh machine would have. Use `${ARCH}` directly.
- **No CLI or config changes.** This is a kit-content patch only; the agentbox binary's surface is identical to v0.4.0.

## v0.4.0 (2026-05-06)

**Features**

- **Kit-image registry distribution** — `agentbox build` and `agentbox run` now try `podman pull` before building locally. On a cold machine with an eligible kit list, the image arrives in seconds instead of minutes. Eligibility: all resolved kits must be built-in kits (no user kit shadows a built-in by name); `[registry] enabled = true` (the default); `--no-pull` not passed. Pull failures are classified (`NotFound`, `Auth`, `Network`, `Unknown`) and always fall through to local build — the pull path never aborts. After a successful pull, the remote ref is retagged as the canonical local tag (`agentbox/<sha[:12]>`) and a cache entry is written, so subsequent runs hit the cache with no network call.
- **`[registry]` config block** — four keys: `enabled` (bool, default `true`), `host` (default `"ghcr.io/nklisch/agentbox-kits"`), `verify` (default `"none"`; `"cosign"` is reserved but rejected at parse time), `pull_timeout` (default `"5m"`, Go duration string).
- **Four pre-published multi-arch kit-list images** — `polyglot-containers-claude`, `polyglot-containers-codex`, `polyglot-claude`, `node-claude`. Published on every `v*` tag as multi-arch manifests (`linux/amd64` + `linux/arm64`) to `ghcr.io/nklisch/agentbox-kits` via the new `kit-images.yml` CI workflow. Each image carries three tags: `<version>-<sha>` (the CLI's deterministic lookup), `<version>-<nickname>` (versioned alias), and `latest-<nickname>` (rolling alias).
- **New `agentbox build` flags:**
  - `--no-pull` — skip the registry pull; build locally unconditionally.
  - `--emit-context <dir>` — stage the Dockerfile and kit directories to disk for consumption by `docker buildx build --push`. Refuses to write into a non-empty directory. Mutually exclusive with `--print`, `--list`, `--prune`.
  - `--print-tag` — print the deterministic local tag (`agentbox/<sha[:12]>`) without building. Used by CI to derive the remote tag suffix.
- **`--no-pull` on `agentbox run`** — threads through to the builder so a single flag skips the pull for the entire run path.
- **`registry-reachable` doctor check** — warn-only HEAD probe of GHCR's manifest endpoint for the `latest-polyglot-containers-claude` alias. Never blocks runs.
- **`sccache` and `cargo-watch` from prebuilt binaries** — the `polyglot` and `rust` kits now install both tools from GitHub-release binaries instead of `cargo install`. The previous approach OOM-killed on memory-constrained hosts (~3-4 GB RSS at link time) and made QEMU-emulated `arm64` CI builds of the polyglot kit infeasible.

**Implementation notes**

- Cache entries gain a `source` field: `"registry"` (pulled) or `"local"` (built). Old entries without the field decode cleanly; `HasMatch` is unaffected.
- Pull-then-fall-back runs *after* the existing cache check, so a previously-pulled image short-circuits on subsequent runs without touching the registry.
- GHCR public packages are free (unlimited storage and bandwidth) for the public agentbox repo. No recurring cost.
- The `verify-matrix` step in `kit-images.yml` guards against drift between `.github/published-kits.yml` (the catalog) and the workflow matrix — the job fails loudly if the two disagree.
- Known limitation: `agentbox doctor`'s `registry-reachable` check surfaces a spurious "auth required" warning on a working setup because GHCR's OCI manifest endpoint requires bearer-token negotiation even for public images, which a raw HTTP HEAD cannot perform. The CLI's actual pull path is unaffected (`podman pull` handles the negotiation transparently). Tracked in SPEC.md "Open / deferred".
- Full design in `docs/features/registry-images.design.md`.

## v0.3.0 (2026-05-05)

**Features**

- **Zellij layout system** — `agentbox run --layout <name>` (and `[zellij] layout = "..."` in config) selects the run-mode pane shape. Three built-ins:
  - `focus` (default) — agent + git status + btm. The previous default, now named.
  - `reviewer` — agent (50% width) + live `git diff` against base branch (50% width, delta-rendered, side-by-side at ≥160 cols) + project-aware test runner that reruns on file change via watchexec. Detects test command from `Makefile`, `Cargo.toml`, `go.mod`, `package.json`, `pyproject.toml`/`pytest.ini`; falls back to a placeholder pane when none detected. Override via `AGENTBOX_REVIEWER_TEST_CMD` env var.
  - `auditor` — agent (60% rows) + live trail of Claude Code tool calls (40% rows) rendered with one color-coded line per event. Claude-only in v1.
- **Custom layouts** — drop a KDL file at `~/.config/agentbox/layouts/<name>.kdl` and reference it by name. agentbox templates `{{.ProjectAbs}}`, `{{.Shell}}`, `{{.AgentCommand}}`, `{{.AgentArgs}}`, `{{.AgentCmdFull}}`, `{{.TrailFile}}` into the file before zellij parses it. See [docs/LAYOUTS.md](docs/LAYOUTS.md).
- **Agent activity trail (auditor only, Claude only)** — agentbox writes a session-merged Claude settings file containing `PreToolUse`/`PostToolUse`/`PostToolUseFailure`/`Stop`/`StopFailure` hooks and **shadow-mounts** it on top of the existing `~/.claude` bind-mount. The user's host `~/.claude/settings.json` is bit-identical before and after the run; agentbox never writes to it. Hooks append JSONL events to `<state>/trail.jsonl`, which a new `box-trail` helper tails and renders. See [docs/TRAIL.md](docs/TRAIL.md).
- **New base-kit helpers:** `box-diff-watch` (delta diff dashboard for the reviewer pane), `box-tests-watch` (project-aware test runner), `box-trail` (color-coded JSONL renderer), `agentbox-hook-record` (the trail hooks call this).

**Implementation notes**

- Live Claude Code 2.1.128 hook payload research at design time confirmed two schema drifts the design's first draft missed: `tool_response` (not `tool_result`) and `last_assistant_message` (not `reason`) on Stop events. Both adapted in `box-trail` and the TRAIL.md schema docs before shipping.
- Decoupled architecture: the layout system (focus/reviewer/custom) and the auditor+trail land as separate commits, so trail hooks could have been deferred without affecting the rest. Both shipped.
- Existing tests preserved byte-for-byte across the focus rename — the original layout still generates the same KDL.

## v0.2.5 (2026-05-05)

**Improvements**

- **Agent pane drops into the rich `zsh -l` shell when the agent exits.** Previously, exiting `claude` (`/exit`, Ctrl+C, crash, etc.) left the pane in whatever default shell zellij respawned — typically not your configured zsh+starship. New base-kit helper `box-agent` wraps the configured agent command and `exec zsh -l`s on exit, with a one-line "agent exited (code N); dropping into zsh" banner so the transition is obvious. The wrapper is applied automatically by the run-mode layout.
- **Git pane is now a proper dashboard.** The pane previously ran `watch git status -sb` (plain text). New base-kit helper `box-git-watch` renders a small grouped dashboard with colored sections for the branch + dirty files (`git status -sb`) and the last 5 commits with refs (`git log --oneline --decorate -5`). `watch --color` preserves ANSI through to the pane.
- **Kit rebuild happens automatically.** Both helpers ship in the base kit, so the next `agentbox run` (or `agentbox run --fresh`) detects the new kit hash and rebuilds the image; no manual action needed beyond reinstalling the binary.

## v0.2.4 (2026-05-05)

**Improvements**

- **Git pane shows the branch.** The zellij git-status pane was running `watch git status -s`; `-s` (short format) intentionally hides the branch header. Switched to `-sb`, which adds `## main...origin/main [ahead N, behind M]` (or `## HEAD (no branch)` when detached) above the file list. One-character fix, big legibility win.

## v0.2.3 (2026-05-05)

**Improvements**

- **Zellij tab bar and status bar are now visible inside the box.** The generated layout wraps every tab in a `default_tab_template` that ships zellij's built-in `tab-bar` (top, 1 row) and `status-bar` (bottom, 2 rows) plugins. Users can now see the active mode (pane / tab / session / search / move / resize) and its keybinds at all times — no more guessing how to detach. Total chrome cost: 3 rows.
- **README detach instruction corrected.** Fixed `Ctrl+p d` → `Ctrl+o d` (`Ctrl+o` enters session mode; `d` detaches). The wrong keybind had been documented since v0.1.0.

## v0.2.2 (2026-05-05)

**Fixes**

- **`podman create: exit status 125` when `containers.enable = true`.** Latent bug exposed by v0.2.0's flip of the default. `runspec` was emitting `--security-opt seccomp=/etc/agentbox/seccomp/containers.json` — an in-container path. Podman reads `--security-opt` from the **host** filesystem at create time, before the container's filesystem exists, so the lookup failed and create exited 125. Fix: use the host path (`in.SeccompPath`) populated by lifecycle. The in-container bind mount is preserved for in-box introspection.
- **`podman create: exit status 125` was opaque.** The runtime was discarding podman's stderr (`cmd.Stderr = io.Discard` in `internal/container/podman.go`), so failures surfaced only as exit codes. `Create`, `Start`, and `Stop` now capture stderr and include the trimmed message in the returned error so users see *why* podman failed.

## v0.2.1 (2026-05-05)

**Fixes**

- **Claude Code agent works in fresh boxes.** Two issues stacked: (1) Claude Code refuses `--dangerously-skip-permissions` when running as root ([claude-code#9184](https://github.com/anthropics/claude-code/issues/9184)), and (2) only `~/.claude/` was bind-mounted, not the sibling `~/.claude.json` where Claude Code stores its primary config. v0.2.1 sets `IS_SANDBOX=1` on the box (the community-known bypass for the root refusal) and adds a sibling-file mount for `~/.claude.json`. Lifecycle touches the source file empty if missing so podman doesn't bind-mount a directory in its place. Run `agentbox run --fresh` to pick up the new mounts on existing boxes.

## v0.2.0 (2026-05-05)

**Features**

- **Easy install** — `curl | sh` installer, prebuilt tarballs on GitHub Releases (`linux/amd64`, `linux/arm64`, `darwin/arm64`), and `go install` documentation. The installer verifies sha256, idempotently adds `~/.local/bin` to `PATH` via a sentinel-wrapped shell-rc block, and strips the macOS Gatekeeper quarantine attribute on darwin.
- **Config write commands** — `agentbox config set/unset <key> <value>`, `agentbox config network <mode>`, `agentbox config containers on|off`, and `agentbox config kits add/remove <name>` for scripted, non-interactive config mutation without opening `$EDITOR`. Writes atomically; validates before touching disk.
- **Containers enabled by default** — `containers.enable` now defaults to `true`. The `containers` kit was already in `default_kits`; the runtime privileges now match, so `docker run` inside a fresh box works without extra config.

**Improvements**

- Base kit gains `git-lfs`, `tree`, `make`, `gron`, a `jgrep` wrapper, `gh` (GitHub CLI), and `glab` (GitLab CLI).
- `agentbox doctor` resolves real binary paths for the sudoers suggestion (via `exec.LookPath` + fallback to install prefix) rather than guessing distro-specific paths.

**Fixes**

- Shell completion docs updated to user-level paths — bash uses `~/.local/share/bash-completion/completions/agentbox`, no `sudo` required.

## v0.1.0 (2026-05-05)

Initial release. All eight ROADMAP phases shipped end-to-end:

- CLI: `agentbox run/shell/exec/attach/ls/rm/build/doctor/config/completion`.
- 12 built-in kits: `base`, six single-language kits (`node`, `python`, `go`, `rust`, `systems`, `cloud`), `polyglot`, three agents (`claude`, `codex`, `opencode`), and `containers` (nested rootless podman).
- Container lifecycle with same-path bind mounts, label-based discovery, persistent state.
- Zellij in-box layout with agent main pane + git status ticker + system stats.
- Network policy: `safe` (DNS threat-feed + IP-level egress filter) and `allowlist` modes via per-box CoreDNS sidecar + `agentbox-netfilter`.
- Nested rootless podman without `--privileged` or host docker socket.
- macOS Apple Silicon support via `podman machine`.
- `--runtime docker` fallback adapter.
